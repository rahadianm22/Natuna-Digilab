# antislop audit 010, 2026-11-09

Scope: all wording of the site, against `antislop.md` and the copywriting skill (v3.2.18). Mode 2 (after): nothing is
changed until specific numbers are approved. Numbers not mentioned are not touched.

Method:
- Rendered all 64 routes in Edge (production build, Next 16.4.3) and collected the visible copy with code samples
  removed: 3,256 unique strings, about 21,000 words, plus 271 aria-label, title, alt and placeholder strings, the page
  titles and the meta descriptions.
- Scanned them for 25 patterns: em and en dashes, the R-16 buzzwords, AI vocabulary, default CTAs (R-15), filler,
  signposting, fake-candid openers, negative parallelism, tail negations, stacked hedges, human verbs on objects,
  exclamation marks, all-caps emphasis, generic closers, unsourced numbers and trust claims (R-17), weasel
  attribution, aphorisms, false ranges, actorless passive, scare quotes, UK and US spelling.
- Read by hand: Home, Docs, Privacy, Build Report, Themes, Naming, Components, the 404 page and the share image text.
- Checked the 145 headings for case and the 72 three-item lists for forced rhythm.
- Checked claims against the repo: license files, GitHub license metadata, `build-report.ts`, the tracker.

## What is already good (not reported)

- No R-16 buzzword anywhere ("seamless", "powerful", "effortless", "intelligent", "ultimate"). No exclamation mark,
  signposting, fake-candid opener, stacked hedge, generic closer or aphorism.
- No inanimate subject with a human verb. No "experts say" style attribution.
- The numbers are sourced. The Build Report figures are copied from the plugin's report frame, and `build-report.ts`
  says never to edit one without the report behind it. Home and Components counts come from the tracker.
- Headings: 145 checked, all sentence case, none Title Case. The only generic one is "Introduction" on /docs, which
  is the normal first label of a docs page, so it stays.
- The four "not just" and "not only" hits are plain instructions ("not just hover", "not only the start"), not the
  "it's not X, it's Y" formula. The three-item lists are real lists (states, keys, properties), not forced trios.
- The quotation marks flagged in /components pages are code literals in props tables. The emoji on /naming and in
  the Figma mapping tables are the real Figma property names, shown on purpose.
- Copy by voice: first person appears only on /privacy ("we do not set cookies") and in demo sentences.
- The Privacy claims hold: no analytics or tracking dependency exists, and the only storage is the theme choice.

## Findings

### HIGH (Hard Gate)

1. The site calls itself open source, and no license says so.
   - Rules: R-36, R-38 (a claim with no evidence behind it).
   - Where: `src/app/layout.tsx:21` ("Open-source components..." in the site description, so it is also the share
     and search snippet), `src/app/docs/page.tsx:47` ("an open design system"), `src/app/docs/page.tsx:152` ("open
     source on GitHub"), `src/app/privacy/page.tsx:20` ("a static, open-source project").
   - Why: the repository is public on GitHub, but neither the org repo nor the personal repo has a license file, and
     GitHub reports `license: null` for both. Code with no license is public, not open source: nobody is allowed to
     copy or reuse it. The Docs page even tells people to copy the components.
   - Fix I would make: say what is true. "Components, design tokens and guidelines built by Natuna Digilab", "a design
     system for digital products", "the source is on GitHub", "a static project whose source is public". If the
     owner wants the label, the owner picks and adds a `LICENSE` file, and the words can come back. I will not choose
     a license.

### MEDIUM (Purpose-Gate)

2. Four demos use the banned default call to action.
   - Rule: R-15 ("See more", "Learn more" as CTAs).
   - Where: `src/components/demos.tsx:329` and `src/components/ComponentPreview.tsx:128` (Card, "See more"),
     `demos.tsx:1271` (Card, `linkLabel="See more"`), `demos.tsx:1423` (Alert, "Learn more").
   - Why: these are the sample sentences people copy into their own screens. A component page that shows "See more"
     teaches the habit R-15 forbids.
   - Fix I would make: name the action the demo content implies, for example "Check installment terms" for the home
     loan card, and "Read the incident notice" for the alert. Demo content is fictional on purpose, so no fact is
     invented.

### LOW (Quality Locks)

3. Spelling mixes UK and US.
   - Rule: none directly. This is the consistency lock: the site should have one voice. The site is mostly US
     ("color" 54 times against "colour" 2, "gray" 16 against "grey" 3).
   - Where: "colour" in `src/app/foundation/page.tsx:155`; "grey" in `src/lib/components-data.ts:592` (Skeleton);
     "labelled" in `components-data.ts:427`, `src/components/demos.tsx:1758`, `src/lib/component-docs.ts:652`, `:753`,
     `:1101`; "Authorising" in `components-data.ts:472` (PIN Input).
   - Fix I would make: colour to color, grey to gray, labelled to labeled, Authorising to Authorizing. HTML
     attributes such as `aria-labelledby` stay as they are.

4. Two components print a range with an en dash.
   - Rule: R-02 as the copywriting skill applies it (check em and en dashes one last time).
   - Where: `src/ui/date-picker.tsx:211` ("18 – 24 Sep 2026") and `src/ui/slider.tsx:83` ("20 – 80").
   - Why: this is output the component produces, so every app that copies the component inherits it. Screen readers
     read the dash inconsistently, and "to" reads the same everywhere.
   - Fix I would make: "18 to 24 Sep 2026" and "20 to 80". This changes what the component prints, so it is your
     call: the en dash is also correct typography for a range.

5. Two words promise something the page no longer means.
   - Rules: R-16 (AI vocabulary: "crafted") and R-36 (stale claim).
   - Where: `src/app/naming/page.tsx:82` ("taken down after it was crafted"), `src/app/not-found.tsx` ("Every
     component, including the planned ones, is listed on the components page").
   - Why: no component is planned any more, so the 404 sentence repeats the stale wording that audit 009 removed
     from Home. "Crafted" is on the AI vocabulary list and adds nothing.
   - Fix I would make: "taken down after it was built", and "Every component is listed on the components page."

6. Filler and one loose range.
   - Rule: R-36 (filler, false range). Tier LOW.
   - Where: `src/lib/components-data.ts:106` ("and anywhere else it matters", Avatar), `:53` ("Two to four reads at a
     glance", Button Group), `src/app/page.tsx:77` and `src/app/docs/page.tsx:47` ("from banking and payments to
     everyday consumer apps").
   - Why: the first two say nothing the sentence did not already say. The third names real domains but frames them as
     a range, and the site description in `layout.tsx` says the same thing in a plainer way ("for banking, payments and
     consumer apps"), so the product is described two ways.
   - Fix I would make: "Shows identity in tables, comments and headers." "Two to four options stay easy to scan."
     "for banking, payments and consumer apps" in all three places.
