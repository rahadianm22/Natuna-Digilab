# antislop audit 011, 2026-11-09

Scope: everything inside the component pages (56 routes under `/components/`), wording and design, one by one, against
`antislop.md` and the copywriting and ui skills (v3.2.18). Mode 2 (after): nothing is changed until specific numbers are
approved. Numbers not mentioned are not touched.

Method:
- Read the whole rendered text of all 56 pages, component by component: summary, usage, props table, Figma mapping,
  accessibility notes, Do and Don't, related links, demos. About 14,500 words, code samples left out.
- Ran a visual scan on each page in light and dark: every text, background, border, outline, fill and stroke color
  against the 92 palette and role values, gradients, colored shadows, blur, and animations that never end.
- Looked at the rendered demos of Cover, Empty State, Comment and Alert.
- Compared every user-facing string in the usage code with the live demo above it on the 52 pages that show code.
  The page promises that the code "is the same code" as the demo.
- Checked claims in the notes against what exists in the repo.

## What is already good (not reported)

- Colors: 0 values outside the palette on any of the 56 pages, in both themes.
- Gradients: 82 found, all purposeful. The fade at the bottom of a collapsed code block, the shimmer of the Skeleton
  wave, and the `gradient` type of Cover, which is a real Figma variant drawn from the blue-800 to blue-900 ramp.
  No glow, no blur, no decorative orb. The "colored shadows" the scan reported on Date Picker and Stepper are the
  transparent default Tailwind ring, not a glow.
- Endless animations: only the loaders (spinner, indeterminate progress, skeleton, pulse), and every one of them stops
  under reduced motion, as the pages say.
- Wording: no buzzword, no filler, no signposting, no stacked hedge, no inanimate subject with a human verb, no
  invented testimonial or statistic. Props, keyboard and screen reader notes say what the code really does, including
  its limits ("Avatar renders initials only", "the more-options menu is not in code yet", "support for aria-busy
  varies"). That honesty is the opposite of slop.
- The Do and Don't lines are specific to each component, not interchangeable. The Do and Don't entries that repeat a
  rule from the accessibility notes (Link, Icon Button, Checkbox) are redundant but not wrong, so they stay.
- Sample names, amounts and Indonesian formats (Andi Pratama, Rp150.000, "4,5", "Jumat, 18 September 2026") are fictional
  demo content that earlier audits accepted, with one exception, finding 4.

## Findings

### HIGH (Hard Gate)

1. Three "live demo" blocks show something other than the code printed under them.
   - Rules: R-36, R-38 (content that looks real but is not what it claims to be). Every component page says: "This
     demo is live, and the code below it is the same code, imports included."
   - Where:
     - Spinner: the demo (`src/components/demos.tsx:450`) is a loading Button ("Processing"). The code shown
       (`src/lib/component-docs.ts:3050`) is `<Spinner label="Loading transactions" />`. The page never shows the
       Spinner itself in its main example.
     - Empty State: the demo (`demos.tsx:569`) is `scope="error"` with "Couldn't load transactions". The code shown
       is `scope="list"` with "No transactions yet" and "Your transactions will appear here."
     - Card: the demo (`demos.tsx:326`) is a media card, "KPR, Subsidized Home". The code shown is an action card,
       "Promo, Time Savings", with Skip and Apply buttons.
   - Found by comparing strings, so it catches different words, not different props. A demo that differs from its
     code only by a prop would not show up, so I cannot promise the other pages are identical in every prop.
   - Fix I would make: make each demo render exactly the documented code, and keep the current examples in the
     "Variants and states" matrix, where they already belong.

2. The Radio Button page says the Radio Group does not exist.
   - Rule: R-36 (a claim that is no longer true).
   - Where: `src/lib/component-docs.ts:431`, "Grouping and exclusivity belong to the Radio Group, which does not exist in
     code yet." The Radio Group page and its code exist (`/components/radio-group`, In React).
   - Fix I would make: "Grouping and exclusivity belong to the Radio Group."

### MEDIUM (Purpose-Gate)

3. The rules that say when to use a radio group, a select or a combobox disagree with each other.
   - Rule: R-36 (guidance that contradicts itself is not guidance). Consistency lock.
   - Where: Radio Group says "2 to 5" in the Figma note (`component-docs.ts:1672`), "Two to six options"
     (`components-data.ts:428`) and "more than about six: use a select" (`:430`). Select says "Use a Radio group for two to
     four options" (`component-docs.ts:4117`) and "fewer than 3 options: consider a button group or radio"
     (`components-data.ts:196`). A designer with five options gets a different answer on each page.
   - Fix I would make, using the Figma number (2 to 5) as the anchor: Radio Group "Two to five options that people
     should see all at once" and "more than five: use a select". Select "Use a Radio group for two to five options" and
     "Use for five or fewer options: use a radio group". Combobox stays at "fewer than about ten", which does not conflict.

4. A real person's first name is the author in the public Comment demos.
   - Rules: R-38, R-18 (a real person in demo content), your call.
   - Where: `author="Rahadian"` with role "Approver" in `demos.tsx:198` and `:1082`, `ComponentPreview.tsx:311`, and the
     code samples at `component-docs.ts:992` and `:1009`. Every other demo uses a fictional name.
   - Fix I would make: use a fictional name, for example "Siti Nur Aisyah" as the Avatar demo does. If the name is on
     purpose, say so and I leave it.

### LOW (Quality Locks)

5. Three Do and Don't lines read as the opposite of what they mean.
   - Rule: R-36 (unclear instruction).
   - Where: Code Block, Don't: "Omit language context when it aids readability" (`components-data.ts:141`). Table,
     Don't: "Hide horizontal scroll on mobile: let the table scroll inside its container" (`:386`). Pagination, Do:
     "Consider infinite scroll for casual browsing contexts instead" (`:239`), a Do that argues against using the
     component and hedges with "consider".
   - Fix I would make: "Drop the language label when the code is obvious without it." Table, "Cut off columns on mobile: let the table scroll
     inside its container." Pagination moves to the Don't side as "Use pagination for casual browsing: infinite scroll fits that
     better."

6. Alert says "error" where the tone is called danger.
   - Rule: consistency lock.
   - Where: `components-data.ts:272`, "Match color and icon to severity (info, success, warning, error)". The prop, the
     Figma mapping and the Toast page all say danger.
   - Fix I would make: "(info, success, warning, danger)".

7. Two demo details break the site's own formatting.
   - Rule: consistency lock.
   - Where: Toast shows "Rp500,000" with a comma in 5 places (`demos.tsx:179` and `:1066`, `ComponentPreview.tsx:231`,
     `component-docs.ts:865` and `:880`), while every other demo uses the id-ID dot ("Rp500.000"). File Input shows "PNG,
     JPG maks. 5 MB", an Indonesian word on an English site, in 5 places (`demos.tsx:377` and `:1374`,
     `ComponentPreview.tsx:391`, `component-docs.ts:2303` and `:2314`).
   - Fix I would make: "Rp500.000" and "PNG, JPG, max 5 MB". The space after Rp is also mixed ("Rp 412.500" on Home against
     "Rp150.000" in the components, 7 against 17 uses). I leave that one alone unless you pick a style.

8. Cover and Changelog have React code, and their pages hide the "Code" row.
   - Rule: consistency lock (the page contradicts itself).
   - Where: `src/app/components/[slug]/page.tsx:128`. The row is hidden for every documentation frame, but only Artboard,
     Guideline and Document lack code. Cover and Changelog show "This demo is live" and "The component lives in src/ui"
     with no Code row above.
   - Fix I would make: show the row (In React) whenever the component has code, whatever its category.

## Not covered

- Props that differ between a demo and its code without any visible text change (see finding 1).
- The gestures themselves (drag, drop, focus trap). The e2e tests cover some of them, and I did not drive every
  component by hand.
- The 53 code files in `src/ui`, which hold no visible copy beyond what the pages already show.
