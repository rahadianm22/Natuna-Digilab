Scope: fourth review after the audit 004 fixes. Captured in Edge with Playwright. I crawled all 62 sitemap routes plus
/templates and a 404. For each route I recorded console errors, React warnings, page errors, title, description,
Open Graph and Twitter tags, and the h1. I fetched all 364 unique internal hrefs and hash targets. I measured the hero
callouts at 1280 and 1440px with the page in light and dark mode, in both artboard modes, while sending, after
sending, during and after "Send another", and with the over-balance error. I clicked "Copy to Figma" on 10 component

I tabbed through Home and /components/button in both modes. I measured layout shift (CLS) and horizontal overflow on
six pages at 1440 and 390px, and checked anchor landing on /docs, /foundation and component pages. I read the source
behind every finding.

## Findings

### 1. HIGH. Ctrl K search shows results from earlier queries, because tokens share a React key
- Where: the Ctrl K dialog on every page (`src/components/CommandSearch.tsx:176`, `key={r.href}`). The token entries
  share hrefs: every color step uses `/foundation#color` (`:32`), all six radii use `/foundation#radius` (`:47`),
  all text styles use `#typography` (`:54`), and all shadows use `#effect` (`:60`).
- What: React logs "Encountered two children with the same key" and reuses the wrong DOM nodes, so the list grows on
  every query.
  - A fresh "rounded" search shows 16 rows (Rounded/4 to /32 three times) instead of 6.
  - After "blue" and then "rounded", the list shows 66 rows.
  - "subheader" then shows 70 rows. Its one real match comes last, under 15 Rounded rows and about 50 Azure and Sky
    Blue rows (captured in the screenshot).
  - The `result-${i}` ids repeat, so `aria-activedescendant` and Enter no longer point at the row the user sees.
- Why: search is the fastest way to reach a token, and audit 004 #7 made it the way to find renamed components. A
  list that fills with wrong results looks broken and sends people to the wrong section.
- Fix: key by identity rather than destination, for example `key={`${r.group}:${r.title}`}`. Better, give each
  `Entry` an `id` and use it for both `key` and the option `id`. Add an e2e check that types "blue", then
  "subheader", and expects one row and no console warnings.

### 2. HIGH. Every "On this page" link and Foundation chip hides its heading under the sticky header
- Where:
  - /docs (`docs/page.tsx:47-109`).
  - Every component page (`components/[slug]/page.tsx:110-211`).
  - /foundation (`foundation/page.tsx:162-346`).
  - The sticky header is in `Header.tsx:22`.
- What: `scroll-mt-*` is set on each `<section>`, but the `id` that the links target is on the `<h2>` inside it, so
  the margin never applies.
  - Desktop: clicking "Component status" on /docs, "Props" on /components/button, or "Radius" on /foundation leaves
    the h2 at `top: 0`, behind the 65px header. The screenshot shows the heading cut off and the first paragraph
    half hidden.
  - At 390px on /foundation, each of the seven chips puts the heading at `top: 0`, under 121px of header and chip
    row. The heading and its intro sentence are both hidden.
  - The catalog (`ComponentOverview.tsx:201`) puts `scroll-mt-24` on the h2 itself and lands correctly at 96px. It
    is the only place that does.
- Why: the section navigation added in audits 003 and 004 drops readers into a section with no title. On phones they
  cannot see which section they are in, apart from the chip.
- Fix: move the scroll margin onto the element that carries the id. On docs and component pages, add `scroll-mt-24`
  to each `<h2 id>`. On Foundation, add `scroll-mt-40 lg:scroll-mt-24`. Alternatively, set
  `html { scroll-padding-top: 5rem }` in `globals.css`, and add a Foundation-only `scroll-padding-top: 9rem` below
  `lg`.

### 3. MEDIUM. There is no skip link, and component pages have 32 tab stops before the content
- Where: every page (`Header.tsx:22`). Measured on /components/button.
- What: a keyboard user reaches the first stop in `<main>` (the breadcrumb) on the 33rd Tab press. The route is the
  logo, four nav links, Search, theme, GitHub, the sidebar filter, Overview, the Atoms toggle, all 19 Atoms links,
  Molecules, and Not tracked. Home needs 8 presses. No page has a "Skip to content" link.
- Why: this is WCAG 2.4.1. The sidebar makes it worst on the pages people use most. Landmarks help screen-reader
  users, but they do not help sighted keyboard users.
- Fix: make the first child of the header
  `<a href="#main" className="sr-only focus:not-sr-only focus:fixed focus:left-4 focus:top-3 focus:z-50 ...">Skip to
  content</a>`, and give each `<main>` `id="main" tabIndex={-1}`.

### 4. MEDIUM. The /components description says "all 51" and "atoms and molecules", but the page shows 56 in three groups
- Where: /components (`components/page.tsx:12`, `:22`).
- What: the meta description reads "Browse all 51 Natuna Digilab components, 9 ready to use, grouped as atoms and
  molecules." Since audit 004 #6, the catalog shows "All 56" and a third "Not tracked" section. The intro says "51
  components are on the build plan" directly above an "All 56" chip, and nothing on the page explains the
  difference of 5.
- Why: this is the text search engines and link previews show for the index page, and the two numbers disagree on
  screen.
- Fix: change the description to "Browse the 51 Natuna Digilab components on the build plan, 9 ready to use, plus 5
  pages not yet tracked." Add a sentence to the intro: "Five more pages have no tracker row; they are listed under
  Not tracked."

### 5. LOW. The hero artboard is labeled 440 × 956, but it is drawn at about 2:3
- Where: Home hero (`HeroPhone.tsx:103`, and the doc comment at `:29-30`).
- What: the frame label says "440 × 956", the Android frame size. The artboard renders at 296px wide and about 443px
  tall, a ratio of 0.67 against 0.46. The doc comment still says "framed as an Android device", which no longer
  describes the markup.
- Why: designers will read a dimension label on an artboard literally, and in a hero that teaches tokens this label
  is wrong.
- Fix: label it "440 wide" (or "Android, 440 wide"), or drop the size. Update the comment to describe the artboard.

### 6. LOW. /templates is an orphan page that can be indexed
- Where: `src/app/templates/page.tsx:8-11`.
- What: no link points to /templates, and it is not in the sitemap. It returns 200 with "No templates yet", and it has
  no `robots: { index: false }`.
- Fix: delete the route. If it should stay, add `robots: { index: false }` to its metadata.

### 7. LOW. Copy to Figma layer names still number across the whole file
- Where: `src/lib/dom-to-svg.ts:87-90` (one `used` map for the whole export) and `:79` (the `Frame` fallback).
- What:
  - The OTP export has "Background 7", "Label 3", "Row 2" and "Row 3" for the empty boxes, and "Frame".
  - The Drawer export has "Container 6" and "Border 3".
  - The Avatar export has "Natuna Digilab", "Natuna Digilab 2" and "Natuna Digilab 3".
  - The Link export wraps the sentence in "Frame".
  - Audit 004 #4 asked for numbering per parent. Everything else in that fix landed.
- Fix: create the `used` map per group (pass a fresh `Map` into each child walk), so siblings number from 1. Name a
  flex or block wrapper whose children are all text "Text". Name an empty bordered box "Slot".

### 8. LOW. Craft slips
- The global `:focus-visible` rule (`globals.css:279-282`) is unlayered, so it overrides every `focus:outline-none`
  utility. In the Ctrl K dialog, the search input (`CommandSearch.tsx:170`) gets a 2px outline with a 2px offset,
  and the dialog clips it at the top edge (visible in the screenshot). Move the rule into `@layer base`, then
  confirm with a tab pass that every control that sets `outline-none` still shows a ring.
- On the hero, the Subheader dot (`HeroPhone.tsx:128-129`) ends 1px before the "S" of "Send money". In the dark
  artboard it reads as a bullet ("•Send money"). End the leader 4px short of the target: subtract 4 from `reach`
  for left-side callouts.
