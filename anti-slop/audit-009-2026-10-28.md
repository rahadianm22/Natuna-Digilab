## Findings

### 1. HIGH. /components throws a React hydration error, because links sit inside link cards
- Where: /components, live, at both widths (`ComponentOverview.tsx:122-137`, `ComponentPreview.tsx` previews).
- What: every card is an `<a>`, and its thumbnail renders the real component. 15 of those previews contain their own
  `<a>` (Link, Breadcrumbs, Pagination, Navigation Bar, Alert action). The console shows `Minified React error #418`.
  The Link preview I added in `f538acc` contributes at least 2 of the 15. I did not establish which one first
  triggered the error.
- Why: invalid HTML (R-35 asks for a clean console, C-4 for resilience). The browser re-parses nested anchors, so the
  server and client trees differ.
- Fix: stop wrapping the card in an anchor. Make the card a `div` with one stretched link on the title
  (`after:absolute after:inset-0`). The thumbnail stays `inert`, so its links can never be reached.

### 2. HIGH. The status copy disagrees with the data, on three pages
- Where: Home hero line (`page.tsx:55-58`), /components intro (`components/page.tsx:25-30`) and its filter chips
  (`ComponentOverview.tsx:84`).
- What:
  - Home says "46 of 46 components ready in Figma. The 21-day build is in progress." The build is finished.
  - /components says "46 components are on the build plan and 46 are ready today. The rest are scheduled by build
    day", but there is no rest. Two lines below, the chip says "Ready 51". The intro counts `productTracker` (46,
    without the 5 Documentation frames) and the chips count `tracker` (51).
- Why: R-17 and R-36. A number that changes between two lines of one page reads as invented, and "in progress" next to
  46 of 46 reads as stale.
- Fix: count one way everywhere. When `ready === total`, write "All 46 components are ready in Figma." and drop the
  "in progress" and "the rest" sentences. Keep the schedule wording for the day the count drops below total.

### 4. HIGH. The Code Block page says it highlights syntax, and it does not
- Where: `components-data.ts:138`. The component is `src/ui/code-block.tsx`.
- What: the summary says "Displays formatted, syntax-highlighted code snippets." The component is deliberately plain

- Why: R-36, a feature claimed and not shipped. I wrote the component and left the older summary.
- Fix: "Shows read-only code with a copy button, in plain text that keeps 7:1 contrast in light and dark."

### 5. HIGH. 42 links on Build Report are 20px tall
- Where: /build-report chart rows (`VariantChart.tsx:60-64`), at 390 and 1280.
- What: the row is 44px (`min-h-11`), but the link inside is only the text, 20px tall. Foundation says the system
  targets WCAG 2.2 AAA target size.
- Rule: R-03 (44px tap target).
- Fix: `className="flex min-h-11 items-center ..."` on the link, so the whole row is the target.

### 6. HIGH. Several components are narrower than 44px
- Where (measured at 390 and 1280, on the live demos): Toast "Undo" 41x44, Comment "Reply" 33x44, OTP digits 40x48,
  Date Picker days 35 to 39 x 44, Search input 42, Combobox input 36, Amount Input 42.
- What: each sets `min-h-11` (or close) and nothing for the other side. These are the system's own components, so
  consumers inherit the size.
- Rule: R-03. Lower real-world impact than 5, because the other side is within 11px of the limit, and a day cell in a
  7-column calendar at 390px cannot reach 44 wide without a second layout.
- Fix: `min-w-11` on Undo and Reply, `min-h-11` on the three inputs. For OTP and Date Picker, either accept 40 and
  write it in the component's a11y note, or size up at the breakpoint where it fits. Your call.

### 7. MEDIUM. Build Report hero stacks four decorations that stand for "tech"
- Where: `build-report/page.tsx:36-50,73`.
- What: a 48px grid of lines (`opacity 0.07`), a lime radial glow and a blue radial glow, a pulsing lime dot that marks
  nothing live, and lime on the eyebrow, the dot, "750 variants.", one stat card, the "to" chip and the arrow.
- Rules: R-07 (background grid), R-01 (radial orbs), R-13/R-19 and the status-dot entry (an endless pulse with no
  state behind it), and one deliberate accent (core Part 3). The Home Foundation band is the same navy with none of
  this, so it also breaks the site's own consistency.
- Fix, by default: delete the grid and both glows, delete the dot (keep "Natuna Build Report" and the date), keep lime
  on the "0 raw hex" card only, which is the number that matters. If you want the grid or glow kept, say why in one
  line (R-37).

### 8. MEDIUM. Motion goes beyond the declared MOTION 1, and the cursor has no stated purpose
- Where: hero `.rise`, `Reveal` on 6 sections (3 on Home, 3 on Build Report), `CountUp`, the chart bar growth
  (`VariantChart.tsx`), and `DotCursor.tsx` with `globals.css:712-770`.
- What: audit 001 set MOTION 1 ("hover and focus only"). The owner added entrances, scroll reveal, count-up and a
  trailing cursor later (commits `6c47612`, `93010de`, `b4599e4`). That is MOTION 2 or higher, so the declaration is
  out of date. All of it respects `prefers-reduced-motion`.
- The cursor is the part that needs a reason: it hides the system cursor on the whole site (`cursor: none !important`)
  and replaces it with a dot and a lagging ring. The system cursor already signals what is clickable. While selecting
  text in a paragraph or a code block, only the dot shows. No file says what it is for.
- Rules: R-19 (motion matches the dial, purpose written down), R-31.
- Fix: declare MOTION 2 for the marketing pages and write one line per effect in `DESIGN.md` (finding 16). For the
  cursor, I recommend removing it: it is the only item here with a usability cost. If you keep it, write the purpose,
  and keep the system cursor over text blocks and code.

### 9. MEDIUM. The component copy is a template: 55 of 55 start with "Use", and 55 of 55 have exactly two Do and two Don't
- Where: `components-data.ts`, every entry (`usage`, `do`, `dont`).
- What: counted, not estimated. "Use when...", "Use for...", "Use in..." on every line, and a 2 + 2 list on every
  component, whether the component has one real rule or five. The pairs for simple components (Separator, Divider)
  read as padded.
- Rules: R-14 (identical structure with no hierarchy reason), C-1, copywriting "Rule of Three" family.
- Fix, two parts. Safe and mechanical: vary the openers ("A card holds one record...", "Reach for Tabs when...").
  Needs your input: the number of rules per component. I will not add rules I cannot source, so I would only cut the
  weakest line where a component has one, and leave the rest to you.
